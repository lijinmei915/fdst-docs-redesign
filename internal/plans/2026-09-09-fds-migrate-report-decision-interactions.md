# fds-migrate 报告处理交互设计

## 目标

在现有逐条提示词抽屉基础上，为 HTML 明细报告增加人工决策能力：有候选 Token 的 finding 可直接选择具体 Token；没有候选 Token 的 finding 可填写处理说明；页面统一汇总所有已处理项并生成一份可复制的处理提示词。

## 交互与数据边界

- 候选选择直接使用本次报告 `finding.candidates`，不得输入或构造候选列表外的 Token。
- 选择候选即视为该 finding 已纳入汇总；清空选择即移出汇总。
- 没有候选的 finding 显示处理说明输入框；非空说明即视为已纳入汇总。
- 顶部“汇总提示词”按钮展示已处理数量；数量为零时禁用。
- 汇总提示词可在抽屉中局部编辑，再复制到剪贴板；同一选择集在当前页面会话内保留编辑，选择变化时重新生成，并提供手动“重新生成”恢复标准内容。剪贴板不可用时选中文本供手工复制。
- 人工决策属于 HTML 本地交互状态，不写回 `fds-token-migration-report.json`，也不改变 finding 的扫描状态。
- 浏览器允许时按报告 finding 集合保存本地状态；存储不可用时静默退化为当前页面会话状态。

## 提示词契约

汇总提示词只包含已处理项，并为每项保留 Finding ID、相对文件、行列、属性和原值。有候选的项目记录人工选定 Token 及其解析值；无候选项目记录人工处理说明。页面已有的状态、判定原因、选择器和匹配类型不在汇总中重复输出。

共同约束压缩为三条并只输出一次：限制修改范围与定位失效重扫、保留原值 fallback 与变量优先级、修改后执行 `verify` 和相关测试。人工选择不替代属性兼容性、Catalog 存在性及最新源码检查。

## 验证

- Node 测试覆盖候选选择控件、无候选说明控件、汇总入口和内嵌状态键。
- 全量 `npm test` 与 Skill `quick_validate.py`。
- 生成真实离线报告，在桌面和窄屏验证选择、说明、计数、刷新恢复、汇总预览、复制降级和无水平溢出。
