# 快速开始

## 适用范围

本页说明如何在已经能够加载 FDS CSS 产物的页面中使用 Global Token。项目如何打包或发布该 CSS，请转到 [ShareDev 接入](ShareDev接入.md) 和 [版本与发布](../engineering/版本与发布.md)。

## 1. 引入 CSS

将普通版 `dist/fds-global-tokens.css` 或压缩版 `dist/fds-global-tokens.min.css` 纳入应用的全局样式入口。两份文件的变量和行为一致，同一页面只加载一份。下面是普通 CSS 入口示例，实际相对路径由消费项目决定：

```css
@import url("./fds-global-tokens.css");
```

产物在 `:root` 上声明变量，因此页面不需要逐个复制变量。

## 2. 优先选择语义 Token

```css
.page {
  color: var(--fds-g-color-text-primary);
  background: var(--fds-g-background-main);
}

.primary-action {
  color: var(--fds-g-color-text-inverse);
  background: var(--fds-g-color-primary);
  border-radius: var(--fds-g-control-radius);
  min-height: var(--fds-g-control-height-default);
}

.primary-action:hover {
  background: var(--fds-g-color-primary-hover);
}
```

颜色、间距或字号的数字档位不是业务含义。业务代码不要因为某个当前值看起来合适，就直接把 `Atomic/Map` 当作默认选择。

## 3. 查询 Token

在 [Token 目录](../reference/Token目录.md) 中按用途或 CSS Variable 搜索。目录由 catalog 自动生成，能回溯到 YAML 源文件。

选择顺序：

1. 普通文本、状态、背景、控件、层级和动效使用 Semantic/Base。
2. 页面画布、场景卡片和卡片标题使用 Semantic/Scene。
3. 组件内部细节使用组件包自己的 Component Token。
4. 只有没有合适语义或正在维护 Token 体系时才使用 Atomic/Map。

找不到符合含义的 Token 时，不按命名规律猜一个变量，按 [迁移与常见问题](../reference/迁移与常见问题.md) 记录缺口。

## 边界

- Dark Map 仅提供固定原子色阶，当前不支持暗色 Semantic 或主题切换。
- `--fds-s-card-*` 是页面场景协议，不是 Card 组件 Token。
- 业务私有视觉规则应限制在业务作用域，不进入 `--fds-g-` 或 `--fds-s-` 命名空间。
- 不从 CSS 产物或 Markdown 反向维护 Token。
