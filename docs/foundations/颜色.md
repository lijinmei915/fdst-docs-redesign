# FDS 颜色规范

## 适用范围

本页用于选择品牌色、状态色、文字色、图标色、表面色和边框色，并说明交互状态如何保持一致。状态、文本、表面和边框颜色应优先从 [基础语义](../semantics/基础语义.md) 选择。

## 设计原则

- **先选用途，再看色值。** 页面和组件优先使用 Semantic Token，不根据当前 Hex 直接选择色阶。
- **状态成组使用。** Default、Hover、Active、Disabled 使用已经配对的语义变量，不在组件内临时调亮、压暗或叠加透明度。
- **前景与表面一起评审。** 文字、图标、边框和背景必须放回真实页面层级中判断，不能只看孤立色块。
- **固定结果直接交付。** Base Palette 与 Dark Palette 保存并发布具体 Hex；浏览器运行时不计算色阶。

## 按场景选择

| 场景 | 推荐入口 | 说明 |
| --- | --- | --- |
| 主操作、品牌强调 | `--fds-g-color-primary` | 配套使用 Hover、Active 和 Disabled 状态 |
| 错误、删除和高风险操作 | `--fds-g-color-danger` | 不用红色色阶代替危险语义 |
| 风险提醒 | `--fds-g-color-warning` | 与错误状态区分，不承担阻断含义 |
| 完成、通过和健康状态 | `--fds-g-color-success` | 使用对应浅背景承载低强调反馈 |
| 信息提示 | `--fds-g-color-info` | 不替代主操作或选中状态 |
| 标题和主要正文 | `--fds-g-color-text-primary` | 次要和辅助内容使用对应文本层级 |
| 页面与容器背景 | `--fds-g-background-main`、`--fds-g-background-container` | 通过层级关系建立信息分区 |
| 普通与弱分隔 | `--fds-g-border-default`、`--fds-g-border-subtle` | 焦点和错误使用专用语义 |

## 交互状态

| 状态 | 实心操作 | 浅色反馈背景 |
| --- | --- | --- |
| Default | `--fds-g-color-primary` | `--fds-g-color-primary-background` |
| Hover | `--fds-g-color-primary-hover` | `--fds-g-color-primary-background-hover` |
| Active | `--fds-g-color-primary-active` | `--fds-g-color-primary-background-active` |
| Disabled | `--fds-g-color-primary-disabled` | 由组件禁用协议组合，不临时计算 |

Danger、Warning、Success 和 Info 使用相同的状态结构。完整名称和解析值见 [Token 目录](../reference/Token目录.md)。

## 值域结构

| 类别 | 内容 | `global.source` | 用途 |
| --- | --- | --- | --- |
| Seed | 11 个有彩色系的基准输入 | `manual` | 构建期参考，不供业务直接消费 |
| Base Palette | 11 个有彩色系的固定亮色色阶 | `manual` | 为 Semantic 和组件层提供底层色值 |
| Dark Palette | 10 个固定公司色系的暗色色阶 | `manual` | 为后续暗色 Semantic 提供底层色值 |
| Gray | Gray 色阶及 White、Black 别名 | `manual` | 中性色、文本和表面底座 |
| Special | 4 个旧体系延续的特殊颜色 | `manual` | 兼容明确依赖旧 Special 索引的场景 |
| RGB | 每个有彩色系的基准色阶 RGB 通道 | `derived` | 需要 RGB 通道组合的 CSS 场景 |

当前有彩色系为 1 个 Brand，以及 Amber、Yellow、Yellow Green、Green、Teal、Blue、Indigo、Purple、Magenta、Red 这 10 个固定公司色系。Base Palette 与固定 Dark Palette 都使用 `0-11` 索引，第 `11` 阶是扩展档。Base 的 `0-10` 按现有映射恢复 fx-style 同索引色值：primary→brand、warning→amber、success→green、info→indigo、danger→red，其余同名对应；第 `11` 阶保留原值。Base 第 `8` 阶不再等于 Seed；RGB 仍对应同名第 `8` 阶。Seed 与 fx-style 各色系第 `06` 阶一致（Brand 为 `#FF8000`）；Dark 保留历史设计值，Dark 第 `8` 阶仍是对应公司色 Seed。Dark Map 仅包含 10 个固定公司色系，不包含 Brand。Gray 使用 `1-20`，其中 `1-19` 恢复 fx-style neutrals 同索引值，`20` 保留原扩展值；Special 使用 `1-4`，色值已与旧版一致。完整色阶和具体值见 [Token 目录](../reference/Token目录.md)。

## 使用规则

业务状态使用语义颜色：

```css
.success-note {
  color: var(--fds-g-color-success);
  background: var(--fds-g-color-success-background);
}
```

只有维护 Token 映射、实现组件私有语义或确实没有全局语义时，才直接使用 Palette。RGB Token 只提供通道值，不能单独作为 `color` 属性值。

## Do / Don't

| Do | Don't |
| --- | --- |
| 用语义 Token 表达主操作、状态、文字和表面用途 | 因为当前颜色相同就直接绑定 Atomic 色阶 |
| 成组检查 Default、Hover、Active、Disabled | 在组件内用透明度或运行时颜色函数临时生成状态 |
| 在真实页面背景和层级中评审可读性 | 只看独立色块就判断颜色可用 |
| 需要新用途时先确认现有语义是否覆盖 | 在 SDS、组件或业务页面另建一套同名 Token |

## 来源类型

- `manual` 表示由设计或维护者直接确认的输入/枚举。
- Palette 的 `manual` 表示具体 Hex 由设计侧确认并作为构建输入；打包过程不会从 Seed 重新生成。
- `derived` 表示从已确认颜色中派生的通道数据。

这些标记说明值的维护来源，不代表浏览器运行时行为。

## 边界

- Dark Map 是底层固定值域，本次不新增暗色 Semantic 映射或主题切换行为。
- 不为透明度组合重复维护所有色阶的 RGB，仅保留基准色阶 RGB。
- 组件状态应建立组件语义，不让业务调用方选择原始色阶。
- 浅色交互背景统一使用 0 / 1 / 2，实心交互使用 8 / 7 / 9，禁用使用 4。
- Seed 到 Map 的算法只用于人工对照历史设计；Base 恢复 fx-style 后与算法存在预期差异，算法不覆盖 Palette，也不进入 CI 发布门禁。
