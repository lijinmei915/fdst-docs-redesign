# 阴影与层级

## 适用范围

本页说明 Opacity、Z-Index 和 Shadow 的 Atomic 值域，以及调用方如何通过稳定用途消费它们。

## 设计原则

- **先判断层级，再选择效果。** Z-Index 解决覆盖顺序，Shadow 只辅助表达离开原表面的关系。
- **静态表面默认无阴影。** 页面分区和卡片优先依靠背景与边框，不把阴影作为装饰。
- **层级按用途分区。** Sticky、Popup、Overlay、Modal、Feedback 使用固定区间，组件私有层级限制在所属区间内。
- **透明度不替代颜色语义。** Opacity 会影响整个元素及其内容，文字、边框和背景的弱化优先使用颜色 Token。

## 按场景选择

| 场景 | 推荐入口 | 说明 |
| --- | --- | --- |
| 静态页面和卡片 | `--fds-g-shadow-none` | 默认依靠背景与边框分隔 |
| 激活或焦点强调 | `--fds-g-shadow-active` | 与 Focus Outline 二选一或明确组合 |
| 拖拽中的元素 | `--fds-g-shadow-drag` | 仅在脱离原表面的过程中使用 |
| Dropdown、Select、DatePicker | `--fds-g-shadow-dropdown`、`--fds-g-layer-popup` | 阴影和覆盖层级成组判断 |
| Modal、Drawer、Dialog | `--fds-g-layer-modal` | 方向性阴影由组件契约维护 |
| Message、Toast | `--fds-g-layer-feedback` | 保证反馈高于模态内容 |
| 禁用元素整体弱化 | `--fds-g-opacity-disabled` | 同时保留禁用行为和可访问状态 |

## 当前模型

| 类别 | Atomic 值域 | 推荐语义入口 |
| --- | --- | --- |
| Opacity | `0 / 25 / 50 / 65 / 80 / 100%`，共 6 档 | `opacity-disabled`，保持 50% |
| Z-Index | 0、100、1000、4000、5000、9000 | `layer-base` 至 `layer-feedback` |
| Shadow | None、Active 配方、Drag 配方、Dropdown 配方 | `shadow-none`、`shadow-active`、`shadow-drag`、`shadow-dropdown` |

Z-Index 是用途区间的起点：Sticky 为 100-999，轻量浮层为 1000-3999，Overlay 为 4000-4999，Modal 为 5000-8999，Feedback 为 9000-9999。组件私有层级只能在所属区间内管理。

## Opacity 取值依据

整体透明度按用途保留少量离散值，不按固定步长生成：0 / 100% 是两端，25% 保留较强弱化选项，50% 延续当前 Disabled，65% 参考 Ant Design 加载态，80% 参考 SLDS 轻度弱化取值。数值越大越不透明；这些原子值不自动赋予交互语义。

- Ant Design 6.6.1 的全局快照提供 `opacityImage = 1`、`opacityLoading = 0.65`，不是一套密集的透明度梯度。
- SLDS 固定源码中的传统 Global Opacity 仅有 `0.5 / 0.8`。本次借鉴两者少量、按用途取值的思想，不声称六档是任一平台的原样规范。
- `opacity` 作用于元素整体及其内容；颜色中的 alpha 只影响对应颜色。文字、浅背景和描边的细微差别由颜色语义表达，不扩展整体透明度档位。
- `opacity: 0` 不会自动移除布局、焦点或点击响应；隐藏和禁用行为由调用方控制。

2026-09-07 将原 18 档收敛为 6 档；移除 3/5/6/8/10/12/18/20/22/40/60/75/90%，新增 65%。Disabled、颜色 alpha、遮罩和阴影配方不变。直接消费已删除原子变量的调用方须按用途迁移，不能机械取最近值；本地调整不等于已发布。回退需恢复上一版 Effects YAML 并重新生成 CSS、catalog 和查询资产。

## 使用规则

```css
.dropdown-surface {
  z-index: var(--fds-g-layer-popup);
  box-shadow: var(--fds-g-shadow-dropdown);
}

.dragging-item {
  box-shadow: var(--fds-g-shadow-drag);
}
```

静态表面默认不使用阴影，优先通过背景和边框建立边界。场景卡片已经通过 `--fds-s-card-shadow` 表达这一默认值。

## Do / Don't

| Do | Don't |
| --- | --- |
| 根据覆盖关系选择全局层级入口 | 用任意大数字解决局部遮挡 |
| 只在浮层、拖拽和明确交互中使用阴影 | 给所有卡片和容器增加默认投影 |
| 将 Focus、Active 和 Selected 分开设计 | 同时叠加外发光、Outline 和强边框 |
| 用颜色语义表达细微弱化 | 用整体 Opacity 处理所有次要文字和浅背景 |

## 边界

- 不直接用任意大数字解决覆盖关系；先判断所属的全局层级。
- Modal、Drawer 的方向性阴影和其他组件私有投影不进入 Global Token。
- Active 阴影与 Focus Outline 需要二选一或明确组合规则，避免重复强调。
- Opacity Token 不代替颜色透明度语义。
