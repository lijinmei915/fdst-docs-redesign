# 排版

## 适用范围

本页展示 Catalog JSON 中的排版 Token：Atomic/Map 的字号、行高与字重，以及 Semantic 的 Heading、Text 和场景密度组合。下文的 Token 名称、变量和值由构建器读取 JSON 生成。

## 设计原则

- **层级来自内容结构。** 先判断标题、正文或标签职责，再选择排版组合，不按“看起来够大”临时挑字号。
- **组合完整使用。** Heading 和 Text 同时包含字号、行高和字重，避免只改一个属性破坏节奏。
- **同级保持一致。** 同一页面中承担相同职责的标题和正文使用同一 recipe，不因容器不同随意变化。
- **可读性优先。** 长文本、窄容器和中文混排需要检查换行、行高和信息密度，不能仅验收单行样张。

## 使用建议

标题按内容层级选择下方 Heading recipe，正文使用 Text recipe；选定角色后同时使用字号、行高和字重。页面需要调整信息密度时，对照下方场景密度组合查看行高与间距。组件内部的特殊文字样式应由对应组件规范说明。

## Do / Don't

| Do | Don't |
| --- | --- |
| 根据内容层级选择完整 Heading 或 Text recipe | 只复制字号，遗漏配套行高和字重 |
| 在真实宽度下检查中文换行和多行节奏 | 只用英文短句或单行样张验收 |
| 组件特殊排版回到组件契约 | 在业务页面新增全局排版角色 |
| 弱化内容优先调整语义颜色和信息层级 | 单纯缩小字号制造不可读的次要信息 |

## 边界

- 本页只呈现 Catalog JSON 已收录的 Global 与 Scene 排版 Token。组件专用的排版要求由组件文档另行说明。
- 响应式排版策略需由产品或组件规范确定，不根据本页基础值自行推断。

## 数据来源

Token 名称、变量、解析值、角色表、密度表和 CSS 示例均读取同一份 `release/fds-token-catalog.json`。本页其他文字是使用建议，更新 Token 后仍需人工核对是否适用。
