# 动效

## 适用范围

本页说明动效时长和缓动的 Atomic 值域，以及 Feedback、Context、Disclosure、Prominent 四类 Semantic recipe。

## 设计原则

- **动效服务反馈。** 用户操作与界面响应之间建立因果关系，不为了装饰增加持续运动。
- **按变化规模选择时长。** 小范围反馈短，结构变化适中，显著变化受限使用。
- **进入和退出分别处理。** 新内容出现与旧内容离场的节奏不同，不用一条曲线覆盖所有状态。
- **状态驱动并尊重减弱动效。** 组件根据 Open、Closed、Selected 等状态切换，并核对当前 CSS 对减少动效偏好的处理。

## Atomic 值域

<!-- fds-catalog-table:motion -->

调用方不要把数字档位重新命名成脱离场景的 fast/mid/slow。较长的 Atomic 时长需经过具体场景评审，不自动扩充 Semantic recipe。组件负责决定实际过渡属性、关键帧和是否需要进入/退出两条曲线。

## 四类语义

| 场景 | 示例 | 使用方式 |
| --- | --- | --- |
| Feedback | Button 按压、Toggle、选中标记 | Duration + Easing |
| Context | Tooltip、Dropdown、Popover | Duration + Enter/Exit Easing |
| Disclosure | Accordion、Tree、折叠区、侧栏 | Duration + Easing |
| Prominent | 重要 Notification、较大遮罩、显著位移 | Duration + Enter/Exit Easing，限制频率 |

## 视觉预览

下面使用当前语义 Duration 与 Easing 对比四类任务的节奏。

<div class="fds-demo" data-demo="motion"></div>

```css
.context-menu[data-state='open'] {
  transition-duration: var(--fds-g-motion-context-duration);
  transition-timing-function: var(--fds-g-motion-context-enter-easing);
}

.context-menu[data-state='closed'] {
  transition-timing-function: var(--fds-g-motion-context-exit-easing);
}
```

减少动效的实际覆盖规则以当前生成 CSS 为准，接入时需验证 `prefers-reduced-motion: reduce` 下的行为。

## Do / Don't

| Do | Don't |
| --- | --- |
| 根据 Feedback、Context、Disclosure、Prominent 选择 recipe | 把时长数字重新包装成模糊的 fast、slow |
| 用真实组件状态触发进入和退出 | 用定时器猜测动画何时结束 |
| 为位移、透明度和尺寸变化控制范围 | 同时堆叠过多效果制造干扰 |
| 验证 `prefers-reduced-motion` | 让减少动效用户仍承受循环或大幅位移 |

## 边界

- `motion-duration-0` 用于关闭动效和减少动态效果，不是普通速度档位或停留时长。
- 当前较长时长的用途需按场景审查；Carousel、Progress、循环动画等具体用法仍由组件或业务场景维护，时长 Token 不表示停留时间。
- 本体系不定义弹簧物理参数、关键帧或动画库接口。
- 不用一个全局 Enter 时长覆盖不同尺寸和交互场景。
