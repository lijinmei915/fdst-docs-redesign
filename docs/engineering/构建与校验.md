# 构建与校验

## 适用范围

本页说明如何从 YAML 生成 CSS、catalog 和 Token 目录，以及如何验证源文件、文档链接和示例变量。命令均以项目根目录为当前目录，在 Windows PowerShell 中执行。

## 环境

- Python 3.10+
- PyYAML 与 Python-Markdown，依赖声明见 `requirements.txt`
- 迁移 Skill 另需 Node.js 16+；依赖锁定在 `skills/fds-migrate/package-lock.json`

```powershell
python -m pip install -r requirements.txt
npm --prefix skills/fds-migrate ci --ignore-scripts
npm --prefix skills/fds-migrate test
```

## 日常校验

```powershell
python tools/build.py --check
python -m unittest discover -s tests -p "test_*.py"
python tools/export_catalog.py --check-docs
python tools/build_docs.py --check
git diff --check
```

`build.py --check` 只读取 YAML 并校验，不写 CSS。无参数执行 `build.py` 时会同时生成普通版和 min 版 CSS。`export_catalog.py --check-docs` 重新从 import 图计算预期结果，检查 catalog、Token 目录、正式文档相对链接以及所有 FDS 变量示例。

`docs/` 是正式文档主目录，其中每一篇 Markdown 都纳入链接和示例变量校验。历史计划与旧版资料已移至项目 `internal/` 目录。

颜色算法可按需人工对照：

```powershell
python tools/generate_color_palettes.py --check
```

Base Palette 的 `0-10` 已恢复 fx-style 色值，与历史设计算法存在预期差异。该命令只比较当前 Palette 固定 Hex 与历史参考算法结果，不写文件、不参与正式构建，也不作为 CI 发布门禁。Palette YAML 是构建输入，`build.py` 不会从 Seed 重新生成颜色。

## 重新生成产物

源 YAML 变化后按顺序执行：

```powershell
python tools/build.py
python tools/export_catalog.py
python tools/build_docs.py
python -m unittest discover -s tests -p "test_*.py"
python tools/export_catalog.py --check-docs
python tools/build_docs.py --check
```

生成结果：

| 产物 | 位置 | 用途 |
| --- | --- | --- |
| CSS Variables | `release/fds-global-tokens.css` | 浏览器运行时消费 |
| Minified CSS Variables | `release/fds-global-tokens.min.css` | 生产环境按需直接引入 |
| Hash CSS Variables | `release/fds-global-tokens.<hash>.css` | 按内容版本引入普通版 CSS |
| Hash Minified CSS Variables | `release/fds-global-tokens.min.<hash>.css` | 按内容版本引入生产版 CSS |
| 资源入口清单 | `release/tpl_config` | `fdstCssEntry` 映射到当次 min hash CSS 文件名 |
| Catalog JSON | `release/fds-token-catalog.json` | 精确查询、文档生成和其他只读工具 |
| FDS Apply JSONL | `skills/fds-apply/references/fds-token-search.jsonl` | 查询 Skill 的完整可搜索 Token 快照 |
| FDS Migrate JSONL | `skills/fds-migrate/references/fds-token-catalog.jsonl` | 迁移 Skill 自带的完整 Token 快照 |
| 可视化文档站 | `public/` | Markdown 同源生成的导航、搜索和内嵌 Demo 页面 |

普通版保留来源注释和换行，便于开发与审查；min 版移除注释和非必要空白。两份 CSS 由同一次构建从同一 Token 图生成，声明和值完全一致，不应分别维护。
| Token 目录 | `docs/reference/Token目录.md` | 开发者可读索引 |

## 校验范围

每次 CSS 构建还会为普通版和 min 版各追加一份带 hash 的副本，字节内容与对应固定名文件完全相同。`<hash>` 使用各自最终 UTF-8 文件内容的 SHA-256 前 12 位，与时间、路径无关。相同内容名称稳定，内容变化生成新名称；`--check` 不写任何产物。正式打包在源校验和 CSS 内容生成成功后清空整个 `release/`，删除旧 hash、Catalog 及子目录，再写入当次 CSS 和 `tpl_config`；必须按上述顺序继续执行 `export_catalog.py` 重建 Catalog。`--check` 不清理目录，源校验失败时保留上次产物。历史发布包需在发布侧另行归档；回退构建逻辑时恢复清理步骤前的实现。CSS 和 Catalog 输出目录统一为 `release/`，文档站继续使用自身的 `assets/fds-global-tokens.css`。

`build.py` 在 CSS 写入后生成 `release/tpl_config`，格式参考 `fx-paas-components/build/plugin/extract-entry-webpack-plugin.js`：每行使用 `入口名:文件名`，文件名不含目录，UTF-8 编码并以 LF 结尾。当前只有一个生产入口：

```text
fdstCssEntry:fds-global-tokens.min.<hash>.css
```

清单始终指向当次生成的 min hash 文件，不扫描历史文件。原 `dist/` 消费路径需迁移到 `release/`；回退时恢复构建及消费路径，并重建产物与文档站。

构建器检查 import 文件缺失/循环、schema 与层级、目录与元数据一致性、Token ID、重复定义、未定义引用、反向引用、类型和引用循环，并拒绝源文件中的 CSS Variable、`var()`、`rem`、`calc()` 与长度 Seed。

文档生成器检查：

- catalog、两个 Skill JSONL 与 Token 目录是否为当前 YAML 的可重复生成结果；
- 每个目录项是否来自 catalog；
- 正式文档相对链接是否存在；
- 每个 `--fds-g-*` 和 `--fds-s-*` 示例是否能在 catalog 精确命中。

文档站生成器检查导航中的 Markdown 源、页面输出、共享资产、搜索索引和当前 Token CSS 是否与 `public/` 一致。

## 排查入口

1. YAML 错误先看输出中的源文件与 Token ID。
2. 生成文件过期时执行生成命令，评审 diff 后重跑 `--check-docs`。
3. 文档变量不存在时查询 Token 目录，不按命名规律补写。
4. 相对链接失败时从报错文档所在目录解析目标路径。

## 边界

- 通过校验只说明源和文档契约一致，不等于已经在 ShareDev 环境发布或完成页面验收。
- 不运行会自动改写无关代码的 lint/format/fix 命令。
