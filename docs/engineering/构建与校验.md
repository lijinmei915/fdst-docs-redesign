# 构建与校验

## 适用范围

本页说明如何从 YAML 生成 CSS、catalog 和 Token 目录，以及如何验证源文件、文档链接和示例变量。命令均以项目根目录为当前目录，在 Windows PowerShell 中执行。

## 环境

- Python 3.10+
- PyYAML，依赖声明见 `requirements.txt`

```powershell
python -m pip install -r requirements.txt
```

## 日常校验

```powershell
python tools/build.py --check
python -m unittest discover -s tests -p "test_*.py"
python tools/export_catalog.py --check-docs
git diff --check
```

`build.py --check` 只读取 YAML 并校验，不写 CSS。`export_catalog.py --check-docs` 重新从 import 图计算预期结果，检查 catalog、Token 目录、正式文档相对链接以及所有 FDS 变量示例。

`docs/` 是正式文档主目录，其中每一篇 Markdown 都纳入链接和示例变量校验。历史计划与旧版资料已移至项目 `internal/` 目录。

## 重新生成产物

源 YAML 变化后按顺序执行：

```powershell
python tools/build.py
python tools/export_catalog.py
python -m unittest discover -s tests -p "test_*.py"
python tools/export_catalog.py --check-docs
```

生成结果：

| 产物 | 位置 | 用途 |
| --- | --- | --- |
| CSS Variables | `dist/fds-global-tokens.css` | 浏览器运行时消费 |
| Catalog JSON | `dist/fds-token-catalog.json` | 精确查询、文档生成和其他只读工具 |
| Token 目录 | `docs/reference/Token目录.md` | 开发者可读索引 |

## 校验范围

构建器检查 import 文件缺失/循环、schema 与层级、目录与元数据一致性、Token ID、重复定义、未定义引用、反向引用、类型和引用循环，并拒绝源文件中的 CSS Variable、`var()`、`rem`、`calc()` 与长度 Seed。

文档生成器检查：

- catalog 与 Token 目录是否为当前 YAML 的可重复生成结果；
- 每个目录项是否来自 catalog；
- 正式文档相对链接是否存在；
- 每个 `--fds-g-*` 和 `--fds-s-*` 示例是否能在 catalog 精确命中。

## 排查入口

1. YAML 错误先看输出中的源文件与 Token ID。
2. 生成文件过期时执行生成命令，评审 diff 后重跑 `--check-docs`。
3. 文档变量不存在时查询 Token 目录，不按命名规律补写。
4. 相对链接失败时从报错文档所在目录解析目标路径。

## 边界

- 通过校验只说明源和文档契约一致，不等于已经在 ShareDev 环境发布或完成页面验收。
- 不运行会自动改写无关代码的 lint/format/fix 命令。
