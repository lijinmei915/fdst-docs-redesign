# 命名规则

## 适用范围

本页说明 YAML Token ID、CSS Variable、数字档位和语义名称的写法。完整名称清单只在 [Token 目录](../reference/Token目录.md) 中生成。

## YAML 与 CSS 命名

YAML `props` Key 使用小写 kebab-case，不包含命名空间：

```yaml
color-primary:
  value: '{!color-brand-90}'
```

构建后对应：

```css
--fds-g-color-primary: var(--fds-g-color-brand-90);
```

`--fds-g-` 表示 FDS Global 公共契约。业务私有变量和组件变量不得复用该前缀。

## 数字档位

Atomic/Map 采用领域名加数字或稳定枚举，例如 `spacing-4`、`radius-2`、`font-weight-semibold`。数字表示该领域内部的有序档位，不跨领域比较，也不等于业务语义。

业务代码优先使用 `control-radius`、`control-height-default` 等语义名称。只有在布局组合没有合适语义时，才直接选择 `spacing-*`。

## 语义名称

- 状态色：`color-primary`、`color-danger-hover`、`color-success-background-active`。
- 内容角色：`color-text-secondary`、`background-container`、`border-subtle`。
- 排版 recipe：`typography-heading-3-size`、`typography-body-line-height`。
- 动效 recipe：`motion-context-duration`、`motion-context-exit-easing`。
- 场景协议：`scene-background`、`scene-card-padding`、`scene-card-title-weight`。

名称描述用途，不携带当前具体值。引用方不应从变量名推断值。

## 禁止模式

- 不在 YAML ID 中写 `--fds-g-` 或 CSS `var()`。
- 不使用大写、下划线或连续分隔符。
- 不为长度增加 Seed，也不使用 `rem` 或 `calc()`。
- 不用 `dark` 命名暗示尚未支持的主题。
- 不在 Global 命名空间加入客户、页面或组件私有名称。
- 不根据相邻名称猜测 Token；以 catalog 精确结果为准。

## 边界

重命名已发布 Token 会改变接口契约，必须按版本变更处理。本文只记录规则，不授权重命名或新增别名。
