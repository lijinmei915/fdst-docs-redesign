迁移与常见问题

适用范围

本页帮助业务代码从硬编码或旧变量迁移到 FDS Global Token，并说明查不到合适 Token 时的处理方式。具体变量是否存在，以 Token 目录 为准。

从硬编码迁移

先识别值的用途，再选择 Semantic Token，不按当前颜色或尺寸做机械替换。

/* 迁移前 */
.notice {
  color: #ef4444;
  background: #f3beb8;
}

/* 迁移后 */
.notice {
  color: var(--fds-g-color-danger);
  background: var(--fds-g-color-danger-background);
}

迁移后验证 Default、Hover、Active、Disabled 等完整状态；不要只替换静态截图中出现的一个值。

从旧变量迁移

  1. 查明旧变量的真实用途和所有调用方。
  2. 在 catalog 中按用途查找 Semantic/Base 或 Semantic/Scene。
  3. 对比运行时值只是验证手段，不是映射依据。
  4. 找到稳定语义后逐处替换，并验证主要页面状态。
  5. 没有等价语义时保留旧变量或业务私有变量，记录缺口，不猜新名称。

色阶索引调整

有彩色 Base Palette 与固定 Dark Palette 当前使用 0-11。若从早期 10-120 名称迁移，映射规则为旧索引除以 10 后减 1：

早期索引 当前 0-11 索引
10 / 20 / 30 / 40 0 / 1 / 2 / 3
50 / 60 / 70 / 80 4 / 5 / 6 / 7
90 / 100 / 110 / 120 8 / 9 / 10 / 11

从旧 fx-style 迁移时不按色值贴近，而是保留用户熟悉的索引对应关系：有彩色 00-10 一对一迁移到当前 0-10，当前第 11 阶是扩展档；neutrals01-19 一对一迁移到 Gray 1-19，Gray 第 20 阶是扩展档；special01-04 一对一迁移到 Special 1-4。旧 RGB 和 Dark 色板不自动迁移。

Gray 自身从早期 10-200 名称迁移到当前 1-20 时，仍按旧索引除以 10，例如 color-gray-10 → color-gray-1、color-gray-150 → color-gray-15、color-gray-200 → color-gray-20。

这些都是公开变量的破坏性更名，不提供旧名兼容别名。尤其注意 color-{family}-10、color-{family}-dark-10、color-gray-10 和 color-gray-20 在当前规则中仍然存在，但含义可能已变化；不能只凭变量名仍可解析就认为迁移完成。业务代码应优先迁移到 Semantic Token；确需消费 Atomic Palette 时，按对应色板的索引规则逐项改名并核对解析值。

排版变量调整

当前 YAML 已移除 Typography Token ID 中多余的 typography- 前缀。下表记录 Token ID；对应 CSS Variable 使用 --fds-g-* 前缀：

旧 Token ID 当前 Token ID
typography-body-color、typography-text-color text-color
typography-body-size、typography-text-size text-size
typography-body-line-height、typography-text-line-height text-line-height
typography-body-weight、typography-text-weight text-weight
typography-heading-color heading-color
typography-heading-{1-5}-{size/line-height/weight} heading-{1-5}-{size/line-height/weight}

当前新增的 heading-6-{size/line-height/weight} 不属于旧变量更名，而是独立扩展的语义排版档。固定行高继续使用 line-height-{step}；新增的 line-height-ratio-{step} 是无单位字号倍率，两者不互为别名，也不自动迁移。

精简的全局语义

以下表面别名已收敛到现有 Background 语义：

已删除 Token ID 当前 Token ID
color-surface-page background-main
color-surface-container background-container
color-surface-elevated background-elevated
color-surface-disabled background-disabled
Scene background Base background-main

以下变量已从 Global Token 删除，当前没有全局替代项：

  • control-height-1 至 control-height-6
  • control-height-compact、control-height-default、control-height-large
  • control-radius、container-radius
  • typography-label-size
  • font-family-sans、font-family-code
  • typography-heading-font-family、typography-body-font-family
  • typography-label-line-height、typography-label-weight
  • typography-caption-size、typography-caption-line-height、typography-caption-weight
  • typography-code-font-family

控件高度、控件圆角、字体族、Label、Caption 和 Code 由应用、组件或具体场景负责。除上述已确认调整外，项目没有完整的旧变量映射表，不能根据名称相似自动替换。

常见问题

为什么不直接使用 Palette？

Palette 表达具体值域，不表达业务用途。状态、文本、背景和边框应使用 Semantic Token，后续映射调整时调用方无需重新选择色阶。

--fds-s-card-* 是 Card 组件 Token 吗？

不是。它描述页面场景中多张内容卡片共享的容器规则。Card 内部头部、操作、交互状态和尺寸由组件包维护。

可以新增一个看起来符合规律的变量吗？

不可以。先在 catalog 中精确查询；不存在时需要确认层级、所有权和跨业务稳定性，再从 YAML 源新增并生成产物。

如何覆盖某个业务场景？

在业务根作用域覆盖已发布的 Scene Token，或建立业务私有变量。不要在业务代码中定义新的 --fds-g-* 或 --fds-s-*。

为什么禁用 rem 和 calc()？

当前长度契约是设计确认的固定 px Map，不依赖运行时基础单位计算。若未来调整此原则，需要先修改体系决策和构建校验，不能由单个业务绕过。

是否支持暗色主题或响应式断点？

当前只提供 10 个固定公司色系的 Dark Atomic/Map，不提供暗色 Semantic 或主题切换；响应式断点也未纳入。不要因为存在 color-{family}-dark-* 就推断页面或组件已经支持暗色主题。

校验通过是否代表已经发布？

不代表。校验只确认本地 YAML、生成物、文档链接和示例变量一致；ShareDev 发布链路仍需单独执行并验证。
