版本与发布

适用范围

本页定义源变更后各产物的同步顺序和发布前门禁。公司仓库 https://git.firstshare.cn/fx/fdst 是 FDST 工程的唯一上游真相源；版本号规则、发布责任人和 ShareDev 发布命令尚未确认，本页不代替发布流程。

工程仓库边界

  • 项目12是公司 FDST 仓库的本地工作副本，跟随 origin/master 更新。同步前检查 Git 状态并保护未提交改动；获取上游后先审查差异，再合入并重新生成、校验产物。
  • 项目9是独立项目，不跟随公司 FDST 更新；其代码、Token 和文档不能反向覆盖公司标准。两项目之间不建立跨目录源码依赖。
  • 公司标准的变更应在项目12基于上游源文件完成评审，再按本页流程生成和校验。项目12的本地未提交改动不代表已经进入公司上游；未经明确要求不自动提交或推送。

同步顺序

tokens/fds-global.yml import 图
  -> CSS Variables（普通版 + min 版）
  -> catalog JSON
       -> Token 目录
       -> FDS Apply 查询 JSONL
       -> FDS Migrate 完整 Token JSONL

普通版 CSS、min 版 CSS 和 catalog 都从 YAML import 图生成。Token 目录及两个 Skill 的 JSONL 快照从同一个 catalog 对象生成；Skill 运行时只读取随包资产，不依赖 FDST 仓库，也不自行解析 Markdown 或 HTML。

变更步骤

  1. 在对应 YAML 叶子文件修改 Token，并更新最近一级 imports。
  2. 运行 python tools/build.py --check 和单元测试。
  3. 生成普通版/min 版 CSS、catalog 与 Token 目录。
  4. 更新解释性文档；不手工编辑 Token 目录。
  5. 重跑文档链接、示例变量和生成一致性校验。
  6. 评审变更是否影响公开变量、引用关系或运行时值。
  7. 进入正式发布门禁后，再同步两个 Skill 资产和消费环境。

变更风险

变更 主要风险 发布前要求
新增 Token API 扩大、用途重复 确认层级、命名、所有权和使用场景
修改值或引用 页面视觉行为变化 评审影响范围并验证主要消费路径
重命名/删除 现有调用方失效 先确认引用与迁移策略，不直接发布
调整 schema/import 构建与下游工具失效 构建、catalog 和查询契约联合验证

回退以源 YAML 变更为单位：恢复已评审的上一版 YAML，再重新生成全部产物。不得只回退任一 CSS 或 catalog，否则会造成事实不一致。

发布门禁

以下事项当前为待确认：

  • catalog 来源提交记录方式；
  • 版本号、变更日志和兼容性策略；
  • Token 评审、质量门禁和发布责任人；
  • ShareDev 公共资源注入、灰度、缓存刷新和回退命令；
  • fds-apply、fds-migrate 的正式打包与发布流程。

这些事项确认前，可以生成和验证本地产物，但不能据此宣称已经发布。

边界

  • HTML 分享页和 KDocs 是展示/同步材料，不是发布源。
  • 本项目不自动写入 ShareDev Skill 仓库，也不发布任何包。
  • 本次文档工作不改变现有 Token 值、层级或命名。
