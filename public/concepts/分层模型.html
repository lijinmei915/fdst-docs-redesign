分层模型

适用范围

本页定义 FDS Global Token 的层级职责和依赖方向，用于判断一个值应在哪里维护、调用方应从哪一层消费。

模型

Atomic 原子层
  Seed    有真实派生关系的最小输入
  Map     构建后的具体值域与固定枚举

Semantic 语义层
  Base    跨业务、跨区域成立的基础用途
  Scene   跨业务可复用的页面组合协议

Component 组件层
  由组件包自行维护，不进入本项目

依赖方向固定为：

Atomic/Seed -> Atomic/Map -> Semantic/Base -> Semantic/Scene

允许同级引用，禁止反向引用和循环引用。构建器依据 import 图和每个引用的实际层级执行校验。

各层职责

层级 保存什么 主要读者 是否建议业务直接消费
Atomic/Seed 会参与派生的颜色输入 Token 维护者 否
Atomic/Map 具体色阶、尺寸、字体、透明度、层级、阴影和动效枚举 Token 和组件维护者 仅无合适语义时
Semantic/Base 文本、状态、背景、排版、效果和动效用途 全部开发者 是
Semantic/Scene 页面、场景卡片和卡片标题组合规则 页面开发者 是
Component 组件结构和状态的公开样式契约 组件消费者 按组件 API

当前 Seed 边界

当前只有颜色 Seed，因为有彩色色阶存在真实的构建期派生关系。间距、字号、行高、圆角和动效时长是设计确认的离散 Map 值，不从“基础单位”运行时计算。

示例

业务页面文本应使用：

.record-title {
  color: var(--fds-g-color-text-primary);
  font-size: var(--fds-g-heading-4-size);
}

不要为了获得相同的当前外观而直接绑定灰阶或字号档位。Atomic 的值可能稳定，但它不表达业务用途。

边界

  • Scene 不包含 workbench-*、detail-*、dashboard-* 等业务名称。
  • Global 层不包含 Button、Input、Tab、Card 等组件 Token。
  • 当前模型不包含 Theme 层或暗色 Semantic 分支；固定公司色系的 Dark Map 仍属于 Atomic/Map。
