命名规则

适用范围

本页说明 YAML Token ID、CSS Variable、数字档位和语义名称的写法。完整名称清单只在 Token 目录 中生成。

YAML 与 CSS 命名

YAML props Key 使用小写 kebab-case，不包含命名空间：

color-primary:
  value: '{!color-brand-9}'

构建后对应：

--fds-g-color-primary: var(--fds-g-color-brand-9);

--fds-g- 表示 Atomic/Map 与 Semantic/Base 公共契约，--fds-s- 表示 Semantic/Scene 公共契约。业务私有变量和组件变量不得复用这两个前缀。

数字档位

Atomic/Map 采用领域名加数字或稳定枚举，例如 spacing-4、radius-2、font-weight-semibold。数字表示该领域内部的有序档位，不跨领域比较，也不等于业务语义。

固定 px 行高保留 line-height-{step} 命名；无单位相对行高使用 line-height-ratio-{step}。ratio 明确表示字号倍数，避免把无单位值误解为 rem、百分比或固定高度。

色板数字表示各自色板内的索引。Base Palette 与固定 Dark Palette 使用 0-11，例如 color-brand-0、color-brand-11、color-blue-dark-0、color-blue-dark-11；Gray 使用 color-gray-1 至 color-gray-20，Special 使用 color-special-1 至 color-special-4。不同色板的起始索引不强求一致。

业务代码优先使用 background-container、layer-popup 等已发布语义名称。控件高度和控件圆角由组件契约负责；只有在布局组合没有合适语义时，才直接选择 spacing-*。

语义名称

  • 状态色：color-primary、color-danger-hover、color-success-background-active。
  • 内容角色：color-text-secondary、background-container、border-subtle。
  • 排版 recipe：heading-3-size、text-line-height。
  • 动效 recipe：motion-context-duration、motion-context-exit-easing。
  • 场景协议：content-padding、card-padding、card-title-weight，输出为 --fds-s-*。
  • 密度场景：density-{compact|comfortable|spacious}-{line-height|spacing}，同一密度的排版与间距成对消费。

名称描述用途，不携带当前具体值。引用方不应从变量名推断值。

禁止模式

  • 不在 YAML ID 中写 --fds-g-、--fds-s- 或 CSS var()。
  • 不使用大写、下划线或连续分隔符。
  • 不为长度增加 Seed，也不使用 rem 或 calc()。
  • color-{family}-dark-{step} 仅用于固定公司色系的 Dark Map，不代表已经提供暗色 Semantic 或主题切换能力。
  • 不在 Global 命名空间加入客户、页面或组件私有名称。
  • 不根据相邻名称猜测 Token；以 catalog 精确结果为准。

边界

重命名已发布 Token 会改变接口契约，必须按版本变更处理。本文只记录规则，不授权重命名或新增别名。
