概念/引用与边界

引用与边界

适用范围

本页用于回答“该用 Base、Scene、Map，还是组件/业务私有变量”。判断依据是用途所有权，不是当前值是否相同。

选择顺序

场景 优先层级 示例
文本、图标、状态、表面、边框 Semantic/Base --fds-g-color-text-secondary
全局覆盖层级 Semantic/Base --fds-g-layer-popup
通用页面、场景卡片和标题 Semantic/Scene --fds-s-card-padding
通用间距组合但无现成语义 Atomic/Map --fds-g-spacing-3
组件内部结构或状态 Component 使用组件包公开能力
控件高度、控件圆角 Component 使用组件 Size API 或组件 Token
单个业务或客户专属规则 业务私有变量 使用业务自己的前缀

推荐使用

.status-message {
  color: var(--fds-g-color-danger);
  background: var(--fds-g-color-danger-background);
}

.context-menu {
  z-index: var(--fds-g-layer-popup);
  box-shadow: var(--fds-g-shadow-dropdown);
  transition-duration: var(--fds-g-motion-context-duration);
  transition-timing-function: var(--fds-g-motion-context-enter-easing);
}

这些变量表达调用方真正需要的状态和用途，底层值调整时不需要业务重新选择色阶或数字区间。

不要使用

不要在普通业务状态中直接选择 color-red-*，也不要用 z-index-* 绕过全局层级入口。不要把 --fds-s-card-* 当成 Card 组件内部 padding、标题结构或交互状态。

Seed 只服务构建期派生，业务和组件都不应直接消费 Seed。

无合适 Token 时

  1. 先确认 catalog 中确实没有相应用途。
  2. 判断需求属于全局语义、组件契约还是业务私有规则。
  3. 对局部需求使用私有变量并记录范围，不向 --fds-g- 或 --fds-s- 补猜测名称。
  4. 跨业务稳定需求进入评审，确认后修改 YAML 并重新生成产物。

边界

  • 同级引用允许，但不得形成循环。
  • Semantic 可以引用 Atomic 或同级稳定语义；Atomic 不得反向引用 Semantic。
  • Scene 只组合现有 Base/Map，不保存新的原始值。
